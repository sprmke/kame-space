# 13: Public pages and SEO

The Public Pages gallery, the Page Editor (stay guide, showcase, property landing), custom pages,
share links, and the crawler-facing surfaces (titles, meta, canonical, sitemap, robots, JSON-LD,
soft 404s).

Screenshots: `/tmp/audit/settings-screens/`.

---

## P1

### P1. There is no way to unpublish a page

`public_page_configs.config` carries a `published` boolean, the guest showcase honours it
(`useShowcaseData` renders the not-published state when false), and the editor store reads it back on
save. But the editor exposes **no Publish/Unpublish control** anywhere (grep for publish/unpublish in
`features/dashboard/page-editor` and `features/dashboard/custom-pages` returns nothing). Every page is
created `published: true` and stays live.

Impact: a host cannot take a half-built showcase or stay guide offline. The only alternatives are to
stop editing (it autosaves) or revert content. The route guide describes a Pro-gated "publish" step
that does not exist in the UI.

Fix: add a header switch (Publish / Unpublish) backed by the existing config field, and make
Unpublish require the same plan gate as save.

### P2. The Page Editor has accessibility defects

- **36 `role="tab"` nodes have no accessible name** (template/section tabs), so the editor is
  unnavigable by screen reader.
- React logs **"In HTML, `<button>` cannot be a descendant of `<button>`"** on the editor, which
  produces invalid DOM and unpredictable click targets.
- The editor has no landmark/heading structure for its three panes (templates, canvas, inspector).

### P3. Old public URLs soft-404 instead of redirecting

- `/properties/monaco-2604` (a renamed listing) ends on `/properties` with the generic list and
  `canonical: /properties`, HTTP 200.
- `/hosts/<old-org-slug>` behaves the same.
- The redirect table has the rows; the public handler returns a **relative** `Location` that the SPA
  fetch cannot follow (see 11-L2).

Search engines see a soft 404 and the wrong canonical, so a rename can deindex the listing.

### P4. No per-page SEO fields in the editor

Property landing and showcase configs have headline/subheadline/sections/palette but no title,
description, OG image or canonical override. The only SEO controls live in Property Settings → Search
preview, and that cannot be saved alone (12-S3). A host cannot set a different title for the showcase
than for the listing.

## What works

- **Autosave is real**: a content edit persists in ~1 s and the guest page reflects it (verified on the
  showcase and stay guide).
- **Template picker, device toggle, sections, style and per-section details** are complete and render
  a faithful live preview.
- **Meta/canonical/OG/JSON-LD are correct on indexable detail routes** when served through the
  middleware (title, description, image, breadcrumb JSON-LD).
- **Non-indexable operational routes are explicitly registered** in `publicRoutes.ts` with
  `indexable: false`, so they do not leak into the sitemap.
- **Unknown slugs are handled** at the API layer (404), and the SPA shows the branded 404.
- **Public page configs are per-property and versioned** (`version` field), so future migrations have
  a hook.

## PR-012: what enforcing would have broken

Report-Only hid every one of these. They were found by running the mocked E2E suite on a production build under the exact policy, plus targeted real-Chrome checks.

| Finding                                                                                                                           | Would have broken                                                            | Fix                                                                                                                               |
| --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `connect-src` did not allow Google Fonts. The service worker (`sw.ts`) and the Polotno editor `fetch` the CSS and font files      | Fonts for installed PWAs, marketing studio fonts. 40 reports on public pages | `fonts.googleapis.com`, `fonts.gstatic.com` in `connect-src`                                                                      |
| `frame-src` did not allow Supabase Storage. Booking receipts, IDs and verification PDFs preview in iframes of signed Storage URLs | Every document preview in host dashboards                                    | `https://*.supabase.co` in `frame-src`                                                                                            |
| Live ID verification loads MediaPipe at runtime from jsdelivr and Google Storage, and compiles WebAssembly                        | Liveness check                                                               | Exact-path allowance for the package and model, plus `'wasm-unsafe-eval'`. The bare CDN is **not** allowed, so it is not a bypass |
| `Permissions-Policy: camera=()` blocked `getUserMedia` everywhere. This is already live today and independent of CSP              | Camera capture for live ID verification                                      | `camera=(self)`                                                                                                                   |

Separate defect found on the way: **`@mediapipe/tasks-vision@0.10.22` does not exist on npm** (`0.10.22` was only ever published as release candidates). Every load returned 404, so liveness was skipped on every capture and the verdict could never rise above `unverified` (see `docs/guides/routes/verify.md`). Pinned to `0.10.35`. Verified in real Chrome against the real CDN, wasm and model: the landmarker loads, `detectForVideo` returns `faceLandmarks`, `faceBlendshapes` and `facialTransformationMatrixes` (the keys the app reads), zero violations. With the old policy the same page is refused (`script-src-elem`).

Kept strict, with evidence: `object-src 'none'` stays. Real Chrome renders a PDF in an iframe under it, for a same-origin URL and a `blob:` URL.

## PR-001 and PR-002: production probes (read-only)

`scripts/dev/verify-captcha-enforcement.ts` sends one token-less POST with an empty body to `claim-sd-voucher` (it runs `antiSpamGate` before it validates or reads anything) and one bad-credential password sign-in for `captcha-probe@example.invalid`. Neither can create data.

```
Edge functions (Turnstile)            verdict  enforcing
Supabase Auth (Attack Protection)     verdict  enforcing
```

The probe was first checked against the real handler in all four server states (enforce, disabled, monitor, unset with and without a secret): it reports `enforcing` only when the handler answers `captchaFailed`. The live bundle at `kamespace.com` also carries a Turnstile site key. The docs listed both items as operator-blocked; they were stale.

## PR-006: AI spend ceiling

- `assertPlatformSpendCeiling` now runs **before** the per-org `enforce_quotas` early return. Before, turning quota enforcement off silently lifted the platform-wide USD ceiling too. Default stays 150 USD/day, `0` disables it, an invalid value falls back to 150, and a failed spend read refuses the call.
- `voice-receptionist-start` checks the org and property quota and refuses before it mints a Gemini Live token (pinned by a test).
- Tests: `aiUsageService_platformCap_test.ts` (9). A mutation check confirmed the ordering test fails if the ceiling moves back below the early return.
- Not provable from here: the production value of `AI_PLATFORM_DAILY_COST_USD_CAP` and whether a paid key is configured. Check Super admin, System health.

## Not done

- **Not deployed.** The CSP reaches production with the next Vercel production build from `main`. The AI ceiling change ships with a backend deploy to `develop`, which is the production backend (`kamewave` not needed to merge, but a merge is a deploy).
- **CI wiring.** The gate runs locally as `bun run test:e2e:csp`. Adding it to `.github/workflows/ci.yml` needs a token with `workflow` scope, which the agent does not have. Suggested job: checkout, bun install, Playwright Chromium, `bun run test:e2e:csp`.
- **Four mocked specs fail on a production build with no policy at all** (`guestFormSubmit`, two in `voucherFormApply`, `voucherRedemptionMocked`). They pass on the dev server (the guest form auto-fills a sample ID there, so the specs wait for an uploader that never attaches in a production build), so they predate this change and say nothing about CSP. They are excluded by name from the `csp` project in `playwright.config.ts`. Worth a ticket.

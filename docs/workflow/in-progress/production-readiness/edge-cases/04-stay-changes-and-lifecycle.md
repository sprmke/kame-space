# Stay changes and booking lifecycle (`STAY`)

**Owned elsewhere:** request expiry windows and stale requests (guest-journey J3, J4), saved form progress ([`guest-form-saved-progress-and-submit-recovery.md`](../../../planned/guest-form-saved-progress-and-submit-recovery.md)), trip hub (`guest-trip-hub.md`, in progress). Read `.cursor/rules/booking-workflow.mdc` before changing any transition here.

## How it works today

- Guests cannot request a date change; the trip page tells them to message the host.
- The host can reschedule only from `PENDING_REVIEW` through `READY_FOR_CHECKIN` (`RESCHEDULABLE_STATUSES`). A reschedule sends the booking back to `PENDING_REVIEW` and clears document completions. No guest email.
- The host can edit rate, fees and guest fields from booking detail (`bookingDetailsPatch.ts`). No guest email or consent.
- No-show is a cancellation reason (`no_show`, initiator guest), done by hand.

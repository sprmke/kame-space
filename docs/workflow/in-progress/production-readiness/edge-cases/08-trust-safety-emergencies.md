# Trust, safety and emergencies (`SAFE`)

Prefix is `SAFE` because the trust-safety plan uses `TS-YYYY-…` as its report reference codes.

**Owned elsewhere:** [`guest-trust-safety-reporting.md`](../../../planned/guest-trust-safety-reporting.md) owns reporting listings, hosts and chats, the super-admin queue, enforcement and appeals. It explicitly leaves out: anonymous reporters, host-reports-guest, parking, and refund outcomes tied to a report. Those gaps, plus **real-time help during a stay**, are what this file covers.

## How it works today

- A guest with a problem on arrival can only chat the host. There is no "Get help" path that reaches anyone else.
- Support tickets need a signed-in account (`submit-support-ticket` is `serveAuthenticated`). Most direct-booking guests use the trip link without an account.
- No extenuating-circumstances policy, reason code or waiver exists anywhere in the code.

## Decisions needed (Phase 0)

1. Who staffs SAFE-01 escalations and in what hours (super-admin email + Telegram is the v1 floor).
2. Extenuating circumstances: platform-declared events only, or also individual cases with documents?
3. Can super-admin compel a host refund, or only record a decision and apply reliability consequences? (Guest stay money never passes through the platform.)
4. Anonymous help (SAFE-06): reverses the trust-safety plan's "signed-in only" decision for these two flows.

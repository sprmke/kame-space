# Guest payments and refunds (`PAY`)

**Owned elsewhere:** refund math and the `booking_refunds` table (cancellation plan §4.4, §4.8); amount tampering and races (checklist 35); PayMongo webhook replay (PR-036). Parking money is in [`05-parking.md`](./05-parking.md), subscriptions in [`06-subscriptions-billing.md`](./06-subscriptions-billing.md).

## How it works today

- Guest stay payments are **manual**: the guest pays the host by GCash or bank and uploads a receipt; AI reads the receipt and flags mismatches; the host confirms. PayMongo only handles subscriptions and parking.
- The platform never holds guest stay money, so it cannot refund, hold or claw back. Every refund is the host sending money and marking it sent with a proof upload.
- `cancellation-refund-cron` nudges the host about `pending` refunds and the guest about missing refund details. Nothing escalates past the host.

This is the root of most money risk: **the guest's only protection is the host's goodwill.** The rows below make that visible and add escalation, without changing the manual payment model (moving guest payments onto PayMongo is a separate roadmap item, see cancellation plan §7).

3. Unpaid balance: do we add a guest-side flag that other hosts in the platform can see?

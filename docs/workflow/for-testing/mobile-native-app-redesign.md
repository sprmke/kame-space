# Mobile native app redesign (v3)

**Goal.** Below `lg` (phone and tablet portrait), every screen in the product looks and behaves like an installed native app: host dashboard (property, parking, org), super-admin, public discovery, guest account, active stay and guest flows. Desktop (`lg+`) layout and behavior do not change. No capability is lost on phone; it may move one level deeper (a sheet, a drill-in screen, a named action).

**Permission fallback.** Tabs come from the permission-filtered nav (same source as the sidebar). If a member cannot see Bookings, slot 2 becomes the first permitted operational module (for example Maintenance). If no inbox and no alerts, slot 3 becomes the next module. Today, Work and You are always present.

**Active tab for non-root routes.** A pure `tabForRoute(pathname, scope)` maps every route to a tab (full table in the pages doc). Modules (Finance, Pricing, Team, Settings, …) belong to Work; account, plan, preferences and help belong to You.

### 5c. Work hub (new screen)

- Search field "Find a tool or action": indexes modules, settings sections and common actions (Add booking, Add transaction, Invite teammate, Block dates). Reuse route keys from `_shared/dashboardAssistantRoutes.ts` so search and the assistant's `open_page` agree. Empty match row: "Ask Kame about '<query>'".
- Continue: last three module screens opened in this scope.
- Module tiles grouped like the sidebar (Operations, Guests, Growth, Manage) with counts where data exists (overdue maintenance, reviews needing reply). Permission-hidden modules are hidden; plan-locked modules show a lock pill and open the existing upgrade path.
- Routes: `…/property/:p/work`, `…/parking/:k/work`, `/org/:o/work`. On `lg+` these redirect to the scope dashboard (the sidebar already shows everything).

### 5d. You hub (new screen)

Profile header (name, email, role pill) · Current workspace with Switch · Organization and plan (Plans & Billing) · Notifications (preferences, Telegram bots, this device) · App (theme, install app, Explore / Host mode) · Help & support · Security · Legal · Sign out. Super-admins also see "Super-admin console". Routes `…/you` per scope; `lg+` redirects to the existing profile surface.

### 5e. Workspace switcher

Bottom sheet, large detent: search; All / Properties / Parking segments; org groups with the org itself as the first row ("Sample Stays PH · Organization"); listings with photo, name, status; check on current; footer "Manage workspaces" → org Properties. Switching keeps the current tab where the target scope has the same module, else lands on Today.

### 5g. Bottom layer rules

One bottom layer at a time: tab bar on tab roots and pushed detail screens; `ContextualActionBar` on focused flows, edit forms, selection mode and composers (it hides the tab bar). Sheets sit above both. Toasts sit above whichever is visible, using `--mobile-bottom-bar-h`. The keyboard hides the tab bar (shipped).

### 5h. Motion and state

Push slides in from the right with a 30% parallax on the outgoing screen, pop reverses, tab change cross-fades, sheets spring with detents, large title hands off to the compact bar with opacity only. Full catalogue with durations in design-system §10. Scroll position restores per route key; tab stacks persist in `sessionStorage`; TanStack Query keeps data warm so back navigation never flashes a skeleton.

# Parity inventory: Phase 3 routes (property scope)

Desktop capabilities taken from the route guides (`docs/guides/routes/org/property/{dashboard,bookings,bookings-detail,inbox,notifications}.md`, read 2026-11-20), each with its proposed phone home. When a page is built, this table moves into the route guide's **Mobile (`max-lg`)** section and the "Built" column is ticked. A page is not done while any row has no phone home.

Companion to [`mobile-native-app-redesign.md`](./mobile-native-app-redesign.md), [`-design-system.md`](./mobile-native-app-redesign-design-system.md) and [`-pages.md`](./mobile-native-app-redesign-pages.md).

**What this inventory changed in the plan.** The first draft of the pages doc under-specified these screens. Corrections to apply when each page is built:

| Page           | Missed in the first draft                                                                                                                                                                                                | Fix                                                                                                     |

| Today          | Date-range presets (week, month, year, custom) drive every number; **Marketing today** card; Cash flow + Breakdown charts; Transactions due card; mini calendar with name / price toggle; rejected-review attention item | Added below; Today keeps a period chip in the title row and sections for each card                      |
| Booking detail | The **Progress** stage deck is a full 6-stage pipeline with doc sub-steps, reject document, recheck, Auto / Manual advance, automation triggers, return / proceed pair, cancel, AI receipt override                      | `NextActionCard` is only the live-stage summary; a **Workflow** screen holds the whole deck (see below) |
